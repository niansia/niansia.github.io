V-Skip：把推理链压短，别连「看到的东西」一起删掉

把纯文本的推理链压缩法直接搬到视觉语言模型上，会删掉「看图才说得出来」的词，推理链照样通顺，却和原图断了线，开始出现幻觉。论文把这叫 Visual Amnesia，问题抓得很准；不过它对原因的解释和几个数字，我读完有些保留。

2026-07-266 分钟阅读视觉语言模型思考链幻觉轻量化

arXiv 2026 · 精读

Chain-of-Thought Compression Should Not Be Blind: V-Skip for Efficient Multimodal Reasoning via Dual-Path Anchoring

Dongxu Zhang, Yiding Sun, Cheng Tan, Wenbiao Yan, Ning Yang, Jihua Zhu, Haijun Zhang

论文 ↗

为什么读这篇

视觉语言模型越来越会「先想再答」，但推理链是一个 token 一个 token 生出来的，写得越长，等得越久，KV cache 也越大。纯文本那边已经有不少压缩推理链的方法，例如 TokenSkip：先删掉推理链里不重要的 token，再微调模型，让它学会直接写出精简版。

我原本以为，把这套搬到图片上应该差不多。这篇的标题直接回答了我：Chain-of-Thought Compression Should Not Be Blind，压缩不能是盲的。它把文本方法搬过来时出的问题叫做 Visual Amnesia（视觉失忆）：压缩后的推理链读起来还是很通顺，却跟原本的图片断了线，模型开始产生幻觉。这个名字取得很好，所以我决定把它读完。

这篇在做什么

先看问题。 纯文本的压缩方法判断一个 token 重不重要，看的是语言上的信息量：可以从前文猜到的词，就算多余。可是在多模态推理里，一个 token 重不重要有两个面向。论文的例子是「红色的苹果」：从语言上看，「红色」一点都不意外，但它可能正是推理链里唯一来自图片的证据；删掉之后，后面的推理就只能靠语言上的常识往下走。

再看做法。 V-Skip 分成三步：

  1. 产生并筛选推理链：用一个老师模型对每组「图片＋问题」写完整的推理链，答错的直接丢掉。
  2. 双路打分，联集保留： - 文本路径：token 的 self-information，也就是 −log P，越好猜分数越低。 - 视觉路径：这个 token 在注意力里分给图片 patch 的总量。只取中间 25%～75% 深度的层，每层取最大的那个 head，再对层平均。 - 两条路各自用 (1−γ) 的百分位数当门槛，只要其中一条过门槛就保留。γ 是目标压缩比，0.5 代表大约留一半。
  3. 蒸馏成 LoRA：用压缩后的推理链对模型做 LoRA 微调（r=16，只加在注意力的投影层，3 个 epoch，8 张 RTX 3090）。推论时模型直接写出精简的推理链，不需要再算注意力或打分。

理论包装是「视觉锚定的信息瓶颈」（VA-IB）：在长度限制下，同时最大化推理链和答案的互信息，以及推理链和图片在给定问题下的条件互信息。后者拆开来，就是「只看文本时的不确定性」减去「看了图之后的不确定性」，也就是挑出那些只看文本猜不到、看了图就很确定的 token。

读到这里我发现，整条流程其实就是 TokenSkip 的架构（用 LLMLingua-2 删 token，再用 LoRA 微调），只是多了一条视觉路径。不过论文在相关研究里把 TokenSkip 描述成「让多余的 token 跳过某些层」，跟 TokenSkip 自己公开的说明对不太上。

实验用 Qwen2-VL（2B、7B、72B）和 Llama-3.2-11B-Vision，基准是 MMMU 和 DocVQA 的验证集，另外用 POPE 测物体幻觉。

结果

主表是 Qwen2-VL-7B（MMMU 看准确率，DocVQA 看 ANLS，延迟是端到端的秒数）：

方法 γ MMMU 延迟 DocVQA 延迟
原模型（完整推理链） – 54.1 6.42 91.6 4.87
直接截断 0.5 38.5 3.23 62.5 2.57
LLMLingua-2 0.5 32.4 3.73 38.5 2.93
ASCoT 0.5 33.1 3.91 40.2 3.10
V-Skip 0.7 51.5 4.65 87.9 3.68
V-Skip 0.5 48.2 3.49 83.7 2.71

其他几个我觉得有意思的数字：

  • 颜色词留下多少：γ=0.5 时，推理链里的颜色词 LLMLingua-2 只留下 42.5%、ASCoT 48.2%、V-Skip 89.4%；物体名称分别是 64.8%、69.5%、91.2%。
  • 幻觉：POPE 问的是「图里有没有某个东西」，答案一半是有、一半是没有。原模型回答「有」的比例是 50.4%，两个文本方法压缩后冲到 66.8%（ASCoT）和 64.5%（LLMLingua-2），F1 从 89.1 掉到 77.1 和 78.9；V-Skip 是 51.2%，F1 88.9。
  • 联集比交集好很多：γ=0.5 时，随机删 27.5、只看文本 32.4、只看视觉 40.5（但语法错误率 11.2%）、交集 30.1、联集 48.2（语法错误率 1.3%）。
  • 模型越大越耐压：γ=0.5 时，2B 掉 8.5、7B 掉 5.9、72B 掉 3.2。
  • 视觉分数要从中间层拿：只用前 25% 的层是 41.5，最后 25% 是 46.8，全部平均是 47.1，中间层是 48.2。

读完最在意的三件事

第一，最可怕的是「通顺的幻觉」。 POPE 那张表最让我在意。压缩后的模型不是明显变笨，而是越来越爱说「有」：推理链里的视觉证据被删掉以后，它就退回语言上的常识，比如看到餐桌，就觉得应该也有叉子。推理链本身照样通顺，用户看推理过程也看不出哪里不对。明显的错误大家会去检查，流畅又有自信的错误才难发现，这也是我觉得这篇比「又快了几倍」更值得记住的地方。

第二，论文对「为什么会被删」给了两个方向相反的解释。 图 1 说，「红色」被删是因为它在语言上太好猜；可是方法那一节和 $45.20 的发票例子又说，视觉相关的 token 在语言上很难猜（困惑度高），所以被当成杂讯删掉。这两种说法方向相反，而且照 V-Skip 自己的文本路径，分数高、难猜的 token 本来就会被留下来。另外，LLMLingua-2 其实不是用困惑度，而是一个只读文本的 token 分类器，它根本看不到图。

我自己比较相信的解释是：问题出在「谁在算几率」。如果用看得到图的模型自己来算 −log P，「红色」之所以好猜，不是因为前面说了苹果，而是因为模型看到了图。越是靠图片才说得出来的词，模型越有把握，分数就越低，越容易被当成废话，换句话说，接地接得越好的 token，越会被这种打分方式惩罚。这是我读完觉得最讽刺的地方。

第三，用注意力当「有没有在看图」的证据，我还不太服气。 论文引用对比学习（CPC）的理论，说注意力权重可以当成互信息的下界；但它算的是语言模型解码器里的注意力，这部分是用「预测下一个 token」训练的，不是对比学习。注意力也有不少已知的怪现象，例如某些 token 不管内容是什么都会吸走大量注意力。层的选择对结果影响不小（41.5 到 48.2），也说明这个信号需要细调。

既然打分是脱机做的，不怕多花一点算力，我反而想直接照 VA-IB 的式子算：同一个 token，用「有图」和「没有图」各跑一次，看几率差多少。这才是式子里「看了图之后不确定性下降多少」的直接估计。

数字要对着表看

  • 2.9 倍加速在表里找不到。 摘要和结论都说 2.9 倍，但 Qwen2-VL-7B 的主表里，γ=0.5 时 MMMU 是 6.42 → 3.49 秒、DocVQA 是 4.87 → 2.71 秒，大约 1.8 倍，正文自己也写 DocVQA 是 1.8 倍。
  • 「几乎没有损失」要看压多少。 γ=0.5 时 MMMU 掉 5.9、DocVQA 掉 7.9，我不会说这可以忽略。真的几乎没掉的是 γ=0.9（掉 0.5 和 0.8），但延迟只从 6.42 秒降到 5.89 秒。我觉得比较实际的是 γ=0.7：掉 2.6 和 3.7，快大约 1.3 到 1.4 倍。
  • 直接截断赢过两个文本压缩法。 这是主表里最让我意外的一列：只把推理链截到一半（论文没有定义，我猜是留前半），MMMU 38.5、DocVQA 62.5，都比 LLMLingua-2 和 ASCoT 好很多。我猜是因为视觉语言模型的推理链常常先描述图片、再推理，留前半刚好保住了视觉描述；但这也让我怀疑基准线是怎么跑的。论文说 V-Skip 比 LLMLingua-2 快，是因为后者要「在线过滤」，看起来基准线没有经过同样的 LoRA 蒸馏。最公平的对照应该是 TokenSkip：一样的 LoRA 训练，只差打分方式，这样才知道进步有多少来自视觉分数、多少来自训练。
  • 两个 32.4。 消融表里「只看文本」的 32.4，跟主表 LLMLingua-2 的 32.4 一模一样，我不确定它们是不是同一组实验。
  • 少了「不推理、直接回答」的对照组。 表里「完整推理链」的 MMMU 分数（2B 41.2、7B 54.1、72B 64.5），跟 Qwen2-VL 技术报告的分数（41.1、54.1、64.5）几乎一样。我不知道技术报告是不是用推理链测的，但少了这一列，就看不出推理链在 MMMU 上本身帮了多少。如果直接回答就有 54 分左右，那压到 48.2 的推理链，等于比不推理还慢、还差，压缩推理链的前提，是推理链本身有用。

放到家用显卡上

这篇对个人研究者其实很友善：打分全部脱机做，推论时只是多一个 LoRA，不用额外计算。LoRA rank 的消融表写到，r=16 时训练的显存峰值是 18.5 GB（表里没写是哪个模型，但准确率 48.2 跟 7B 的主表一样，应该是 7B）。这是 8 张卡一起训练时的数字，换成单卡要靠梯度累积，不过看起来一张 24 GB 的卡有机会放得下。

但「模型越大越耐压」那张表让我有点担心。最怕压的是 2B，掉了 8.5 分，作者的解释是小模型的推理链本来就很密，没什么可以删；可是在自己电脑上跑的，偏偏就是这些小模型。最需要省的模型，也最禁不起省，所以小模型可能更需要「看题目决定压多少」，而不是一个固定的 γ。

我的疑问

  • 训练数据从哪里来？ 论文没写老师模型是哪一个，也没写拿哪些数据产生推理链来蒸馏。MMMU 有公开答案的只有 dev（150 题）和验证集（900 题），而评估用的就是验证集，我很想知道训练用的是什么。
  • 推理链很短。 原模型在 MMMU 平均只写 245 个 token，DocVQA 是 189 个，模型也都是 2024 年的。现在会长篇思考的视觉语言模型动不动就写几千个 token，那才是最需要压缩的地方；视觉证据散在长推理链里，被删掉的风险可能更高，但这篇没有测。
  • 不压缩时反而比较慢。 γ=1.0 的 V-Skip（6.54 秒）比原模型（6.42 秒）慢一点，可能是 LoRA 没有合并回权重的开销。差距很小，但「零额外成本」还是要看怎么部署。
  • 没有公开代码。 我读的时候找不到代码，联集门槛、层的选择这些细节没办法自己确认。

读完之后想试的事

  1. 直接估计「看了图多知道多少」：同一个 token，用有图和没有图（或换成空白图）各算一次 log P，把差值当视觉分数，和注意力分数比较，看哪一个更能找出真正的视觉锚点。
  2. 补两个对照组：「不推理、直接回答」和「TokenSkip（同样的 LoRA 训练）」，把推理链本身的价值、训练的效果和视觉分数的效果分开。
  3. 把 POPE 的「有」比例当成固定检查：以后看到任何压缩方法（推理链、视觉 token、量化都一样），都顺手看模型是不是变得比较爱说「有」，这比只看准确率更早发现它开始脱离图片。
  4. 换成会长篇思考的小模型：例如 Qwen3-VL 的小型 Thinking 版本，看视觉锚点在长推理链里分布在哪里，是不是大多集中在开头描述图片的那一段。

论文的数字已对照 arXiv v4（2026 年 3 月 11 日）的 PDF；Qwen2-VL 的分数取自它的技术报告（arXiv 2409.12191）。

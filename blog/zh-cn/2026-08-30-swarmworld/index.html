论文笔记

SwarmWorld：AI agent 不讲话也能合作，那只监控对话还够吗？

一群一模一样的 LLM agent 放进会留下痕迹的世界，不指派角色也会自己分工，而且大多是「路过看到」别人的成品才学会的。推文讲得很震撼，论文本身克制得多；我最在意的是它对 AI 安全的意思：只看 agent 之间的对话，会漏掉很多协调。

2026-08-305 分钟阅读多智能体LLM agentAI 安全集体智能

arXiv 2026 · 精读

SwarmWorld: Stigmergic technological evolution in societies of language-model agents

Subhadeep Pal, Fiona Y. Wang, Markus J. Buehler

论文 ↗代码 ↗

为什么读这篇

在 X 上看到 MIT Markus Buehler 教授的推文，说法很吸睛：一群 AI agent 不用互相讲话也能发明、建造东西，而且把所有 agent 都拿掉之后，它们盖的技术还能自己运作。

真正吸引我的是推文里的一个观点：如果 agent 能通过改变共享环境来协调，那只监控 agent 之间的对话就不够了。这刚好是我关心的 AI 安全问题，所以我点进去把论文读完，想看看数字到底怎么说。

这篇在做什么

SwarmWorld 是一个格子状的仿真世界，有资源、加工站、天气和各种干扰。每个 agent 只看得到自己附近的状况和自己的记忆，然后输出一份有格式限制的行动计划（每次最多 12 个动作）：移动、采集、测试材料、盖设施，或是帮盖好的设施写控制程序。

关键设计是「agent 提案，仿真器决定」。agent 说设计很好没有用，要通过仿真器的物理规则才算数；盖好的设施会一直留在世界里，之后的 agent 走过去就看得到、用得到、改得到。

所有 agent 都一样：同一个模型（gpt-5.6-luna）、同一份 prompt，也没有指派角色。作者用四种条件把不同的机制拆开：

条件 共享世界 沟通 继承程序
完整文化 有 有 有
不能沟通 有 无 有
没有明确文化 有 无 无
各自独立搜索 无 无 无

「没有明确文化」只剩下通过环境留下的痕迹互相影响，也就是论文标题里的 stigmergy（像白蚁盖巢那样）。「各自独立搜索」是让 N 个 agent 各自待在自己的世界，每个指针都取 N 个世界里最好的那个，是很强的对照组。

评估也设计得很干净：把世界冻结、移除所有 agent，拷贝成 8 份，各自丢进没看过的污染、干旱、风暴组合，只让物理和已经装好的程序继续跑，看留下来的技术能不能保护环境。

规模是 50、100、200 个 agent 各跑 800 个 tick，每种设置 4 个世界种子；另外还有 100 个 agent 跑 3,200 个 tick 的长期实验。最后作者也把同一套架构搬到火山材料和蛋白质材料的世界。

推文和论文，差在语气

推文的数字大多对得上论文：

  • 约 95% 的「第一次重用」，是 agent 在世界里直接看到别人的成品，而不是发明者交接给它；直接接触只在最短的时间窗内略高于随机打乱的基准。
  • 完整文化下，100 个 agent 时有 76% 的设施由不只一个 agent 参与建造（50 个时 67%、200 个时 56%）。
  • 有一个控制程序累积了六位作者；最深的程序族谱有 12 条 fork 边（推文说「超过 12」，论文写的是 12）。
  • 随机移除一半的 agent，98.3% 的设施仍然连着至少一个存活的 agent；改成移除链接最多的那些，就掉到 59.6%。

但读完论文，我觉得两边的语气差很多：

  • 推文说「数百个」agent，论文最多是 200 个。
  • 推文说不沟通的社会在广度、韧性和发明数上胜出，这几项论文的数字确实支持，例如长期实验结束时，通过验证的发明平均是：没有明确文化 7.00 个、完整文化 5.75 个、独立搜索 2.75 个。但推文没提另一面，论文自己强调主要结果并不是群体普遍比较强：只比「最强的单一成品」，独立搜索反而赢（0.3488 对完整文化的 0.2380）；50 个 agent 时，完整文化和不能沟通这两组在探索指针上也输给独立搜索；沟通和文化到底有没有帮助，要看时间长短和看哪个指针。
  • 「移除一半还剩 98%」量的是网络图的连通，不是 agent 消失后世界真的能自己修好，论文的限制段写得很清楚。另外，所有结论都来自 4 个种子、1 个模型和 1 套 prompt。

我反而很欣赏论文的克制：作者把「不是普遍优势」写进正文，限制写得很具体，还公开了引擎、原始 trace，以及能验证哈希值的数据。这跟我做研究的原则很像：每个主张都要有能检查、能重现的证据，只是推文为了传播，把这些但书都拿掉了。

最让我在意的：AI 安全的盲点

第一，协调不一定经过对话。 现在谈多 agent 系统的安全，大多是在看 agent 之间传了什么消息。SwarmWorld 显示，就算把沟通整个拿掉，群体还是能通过留下的成品协调，而且第一次重用大多就是「路过看到」。换到现实世界，coding agent 之间也常常不是直接对话，而是通过 repo 里的文件、issue、共享的记忆或数据库接力：一个 agent 留下脚本，另一个 agent 拿去运行。只监控消息的话，这种协调是看不见的。

第二，要监控的是「世界的变化」和它的来源。 论文本身其实给了答案：每个设施都记录了建造者、参与者、材料和完整的程序历史，每段程序都记录作者和它 fork 自谁。这张来源追踪图，正是稽核系统需要的东西：谁改了什么、之后又被谁用了。放到真实的 agent 系统，就是对共享状态的每一次修改记录来源，而不只是存对话纪录。

第三，越会合作，弱点越明显。 随机拿掉一半的 agent 几乎没有损失，拿掉枢纽却损失很大，而且完整文化比没有明确文化更依赖枢纽（59.6% 对 73.9%）：沟通管道越多，结构越集中。这是我读到这里想到的：对攻击者来说，找出枢纽下手，比随机攻击有效得多。反过来，如果有一个被动过手脚的成品被大家「路过看到」就拿去用，扩散也会很快，完整文化下第一次重用的中位数只要 5 个 tick，平均会被 13.53 个非建造者采用，这其实就是供应链风险。

如果换成我跑得动的规模

每个 agent 的每次决策都是调用同一个云端模型，但论文没有写总共调用了几次、花了多少钱。我很好奇的是：分工和「路过学会」这些现象，是不是需要够强的模型才会出现？论文只测了一个模型，这一点还不知道。

好在代码和数据都公开了，而且世界的物理是确定性的，真正花钱的只有 agent 的决策。缩小成二十个左右的 agent、换成家用显卡跑得动的小模型，应该就能先看看分工还会不会出现。

我的疑问

  • 成本没有交代。 200 个 agent、800 个 tick，需要多少次模型调用、多少费用，对想重现的人很重要。
  • 只有一个模型。 换小模型，或是混用不同家的模型（异质的群体），分工和重用的模式会不会改变？
  • 「发明」由仿真器定义。 材料和功能都是仿真器规定的，搬到真实世界会怎样还很难说；作者也把提高仿真的真实度列为下一步。
  • 种子数少。 每种设置只有 4 个种子，作者用配对的 bootstrap 区间报告效果大小，但有些区间还是很宽。

读完之后想试的事

  1. 用公开的 trace 自己重算「第一次重用」的来源比例，确认 95% 这个数字。
  2. 做一个缩小版：二十个 agent、小模型，在自己的显卡上跑，看分工还会不会出现。
  3. 从安全的角度加一个实验：在世界里放一个有问题的设施，看它通过「路过看到」扩散得多快，只监控消息的话能不能发现。
  4. 想想这种来源追踪图能不能用在实际的 coding agent 上：记录每个文件是谁写的、之后被谁运行。

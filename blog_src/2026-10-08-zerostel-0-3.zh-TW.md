[Zerostel](https://github.com/zerostel/zerostel) 10 月 8 日發布 [0.3.0](https://github.com/zerostel/zerostel/releases/tag/v0.3.0)。`zerostel checks` 和 `zerostel log` 現在會直接列出哪些測試失敗，從已經記錄下來的輸出讀出來，支援 vitest、jest、pytest、go test、cargo test 等常見的測試工具，MCP 的 `checks` 工具也會帶上這份清單。MCP 工具都補上了標題和註記，寫明會對電腦做什麼：只有 `rewind` 會改專案檔案，`checkpoint` 只新增快照，其他都只讀取，也沒有任何工具會連網。

護欄規則改成照 shell 實際執行的方式解讀指令。以前 `git reset --hard*` 這類規則抓不到 `"git" reset --hard`、`\rm -rf x`、`sudo -u root rm -rf x` 或包在 `bash -c '...'` 裡的寫法，現在會先拆掉引號、反斜線、`sudo`、`env` 這類包裝和程式的完整路徑再比對，規則只會比以前抓到更多，不會變少。同時加上 property-based 測試，每次執行都會產生上千種被禁止的指令和路徑寫法，確認每一種都還是會被擋下來。

同一天也整理了專案本身：CI 加上 Node 26，官網不再把網站資料夾的 README 當成頁面公開，並新增一頁[隱私說明](https://zerostel.com/privacy/)，寫明 Zerostel 不收集任何資料，紀錄只存在自己電腦的 `~/.zerostel`。Claude Code 外掛搬到獨立的 repo [zerostel/claude-plugin](https://github.com/zerostel/claude-plugin)，裡面的 `dist/cli.js` 和 npm 套件是同一個檔案，準備申請上架 Anthropic 的外掛目錄（[#16](https://github.com/zerostel/zerostel/issues/16)）。接下來要把失敗的測試也顯示在 `zerostel ui` 和 HTML 報告裡，以及能回到某個測試最後一次通過的那一步（[#20](https://github.com/zerostel/zerostel/issues/20)）。

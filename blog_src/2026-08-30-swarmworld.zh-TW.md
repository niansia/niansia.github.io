## 為什麼讀這篇

在 X 上看到 MIT Markus Buehler 教授的[推文](https://x.com/ProfBuehlerMIT/status/2093630309585531033)，說法很吸睛：一群 AI agent 不用互相講話也能發明、建造東西，而且把所有 agent 都拿掉之後，它們蓋的技術還能自己運作。

真正吸引我的是推文裡的一個觀點：如果 agent 能透過改變共享環境來協調，那只監控 agent 之間的對話就不夠了。這剛好是我關心的 AI 安全問題，所以我點進去把論文讀完，想看看數字到底怎麼說。

## 這篇在做什麼

SwarmWorld 是一個格子狀的模擬世界，有資源、加工站、天氣和各種干擾。每個 agent 只看得到自己附近的狀況和自己的記憶，然後輸出一份有格式限制的行動計畫（每次最多 12 個動作）：移動、採集、測試材料、蓋設施，或是幫蓋好的設施寫控制程式。

關鍵設計是「agent 提案，模擬器決定」。agent 說設計很好沒有用，要通過模擬器的物理規則才算數；蓋好的設施會一直留在世界裡，之後的 agent 走過去就看得到、用得到、改得到。

所有 agent 都一樣：同一個模型（gpt-5.6-luna）、同一份 prompt，也沒有指派角色。作者用四種條件把不同的機制拆開：

| 條件 | 共享世界 | 溝通 | 繼承程式 |
|:---|:---|:---|:---|
| 完整文化 | 有 | 有 | 有 |
| 不能溝通 | 有 | 無 | 有 |
| 沒有明確文化 | 有 | 無 | 無 |
| 各自獨立搜尋 | 無 | 無 | 無 |

「沒有明確文化」只剩下透過環境留下的痕跡互相影響，也就是論文標題裡的 stigmergy（像白蟻蓋巢那樣）。「各自獨立搜尋」是讓 N 個 agent 各自待在自己的世界，每個指標都取 N 個世界裡最好的那個，是很強的對照組。

評估也設計得很乾淨：把世界凍結、移除所有 agent，複製成 8 份，各自丟進沒看過的污染、乾旱、風暴組合，只讓物理和已經裝好的程式繼續跑，看留下來的技術能不能保護環境。

規模是 50、100、200 個 agent 各跑 800 個 tick，每種設定 4 個世界種子；另外還有 100 個 agent 跑 3,200 個 tick 的長期實驗。最後作者也把同一套架構搬到火山材料和蛋白質材料的世界。

## 推文和論文，差在語氣

推文的數字大多對得上論文：

- 約 95% 的「第一次重用」，是 agent 在世界裡直接看到別人的成品，而不是發明者交接給它；直接接觸只在最短的時間窗內略高於隨機打亂的基準。
- 完整文化下，100 個 agent 時有 76% 的設施由不只一個 agent 參與建造（50 個時 67%、200 個時 56%）。
- 有一個控制程式累積了六位作者；最深的程式族譜有 12 條 fork 邊（推文說「超過 12」，論文寫的是 12）。
- 隨機移除一半的 agent，98.3% 的設施仍然連著至少一個存活的 agent；改成移除連結最多的那些，就掉到 59.6%。

但讀完論文，我覺得兩邊的語氣差很多：

- 推文說「數百個」agent，論文最多是 200 個。
- 推文說不溝通的社會在廣度、韌性和發明數上勝出，這幾項論文的數字確實支持，例如長期實驗結束時，通過驗證的發明平均是：沒有明確文化 7.00 個、完整文化 5.75 個、獨立搜尋 2.75 個。但推文沒提另一面，論文自己強調**主要結果並不是群體普遍比較強**：只比「最強的單一成品」，獨立搜尋反而贏（0.3488 對完整文化的 0.2380）；50 個 agent 時，完整文化和不能溝通這兩組在探索指標上也輸給獨立搜尋；溝通和文化到底有沒有幫助，要看時間長短和看哪個指標。
- 「移除一半還剩 98%」量的是網路圖的連通，不是 agent 消失後世界真的能自己修好，論文的限制段寫得很清楚。另外，所有結論都來自 4 個種子、1 個模型和 1 套 prompt。

我反而很欣賞論文的克制：作者把「不是普遍優勢」寫進正文，限制寫得很具體，還公開了引擎、原始 trace，以及能驗證雜湊值的資料。這跟我做研究的原則很像：每個主張都要有能檢查、能重現的證據，只是推文為了傳播，把這些但書都拿掉了。

## 最讓我在意的：AI 安全的盲點

**第一，協調不一定經過對話。** 現在談多 agent 系統的安全，大多是在看 agent 之間傳了什麼訊息。SwarmWorld 顯示，就算把溝通整個拿掉，群體還是能透過留下的成品協調，而且第一次重用大多就是「路過看到」。換到現實世界，coding agent 之間也常常不是直接對話，而是透過 repo 裡的檔案、issue、共享的記憶或資料庫接力：一個 agent 留下腳本，另一個 agent 拿去執行。只監控訊息的話，這種協調是看不見的。

**第二，要監控的是「世界的變化」和它的來源。** 論文本身其實給了答案：每個設施都記錄了建造者、參與者、材料和完整的程式歷史，每段程式都記錄作者和它 fork 自誰。這張來源追蹤圖，正是稽核系統需要的東西：誰改了什麼、之後又被誰用了。放到真實的 agent 系統，就是對共享狀態的每一次修改記錄來源，而不只是存對話紀錄。

**第三，越會合作，弱點越明顯。** 隨機拿掉一半的 agent 幾乎沒有損失，拿掉樞紐卻損失很大，而且完整文化比沒有明確文化更依賴樞紐（59.6% 對 73.9%）：溝通管道越多，結構越集中。這是我讀到這裡想到的：對攻擊者來說，找出樞紐下手，比隨機攻擊有效得多。反過來，如果有一個被動過手腳的成品被大家「路過看到」就拿去用，擴散也會很快，完整文化下第一次重用的中位數只要 5 個 tick，平均會被 13.53 個非建造者採用，這其實就是供應鏈風險。

## 如果換成我跑得動的規模

每個 agent 的每次決策都是呼叫同一個雲端模型，但論文沒有寫總共呼叫了幾次、花了多少錢。我很好奇的是：分工和「路過學會」這些現象，是不是需要夠強的模型才會出現？論文只測了一個模型，這一點還不知道。

好在程式碼和資料都公開了，而且世界的物理是確定性的，真正花錢的只有 agent 的決策。縮小成二十個左右的 agent、換成家用顯卡跑得動的小模型，應該就能先看看分工還會不會出現。

## 我的疑問

- **成本沒有交代。** 200 個 agent、800 個 tick，需要多少次模型呼叫、多少費用，對想重現的人很重要。
- **只有一個模型。** 換小模型，或是混用不同家的模型（異質的群體），分工和重用的模式會不會改變？
- **「發明」由模擬器定義。** 材料和功能都是模擬器規定的，搬到真實世界會怎樣還很難說；作者也把提高模擬的真實度列為下一步。
- **種子數少。** 每種設定只有 4 個種子，作者用配對的 bootstrap 區間報告效果大小，但有些區間還是很寬。

## 讀完之後想試的事

1. 用公開的 trace 自己重算「第一次重用」的來源比例，確認 95% 這個數字。
2. 做一個縮小版：二十個 agent、小模型，在自己的顯卡上跑，看分工還會不會出現。
3. 從安全的角度加一個實驗：在世界裡放一個有問題的設施，看它透過「路過看到」擴散得多快，只監控訊息的話能不能發現。
4. 想想這種來源追蹤圖能不能用在實際的 coding agent 上：記錄每個檔案是誰寫的、之後被誰執行。

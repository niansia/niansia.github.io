## 為什麼讀這篇

視覺語言模型越來越會「先想再答」，但推理鏈是一個 token 一個 token 生出來的，寫得越長，等得越久，KV cache 也越大。純文字那邊已經有不少壓縮推理鏈的方法，例如 TokenSkip：先刪掉推理鏈裡不重要的 token，再微調模型，讓它學會直接寫出精簡版。

我原本以為，把這套搬到圖片上應該差不多。這篇的標題直接回答了我：Chain-of-Thought Compression Should Not Be Blind，壓縮不能是盲的。它把文字方法搬過來時出的問題叫做 Visual Amnesia（視覺失憶）：壓縮後的推理鏈讀起來還是很通順，卻跟原本的圖片斷了線，模型開始產生幻覺。這個名字取得很好，所以我決定把它讀完。

## 這篇在做什麼

**先看問題。** 純文字的壓縮方法判斷一個 token 重不重要，看的是語言上的資訊量：可以從前文猜到的詞，就算多餘。可是在多模態推理裡，一個 token 重不重要有兩個面向。論文的例子是「紅色的蘋果」：從語言上看，「紅色」一點都不意外，但它可能正是推理鏈裡唯一來自圖片的證據；刪掉之後，後面的推理就只能靠語言上的常識往下走。

**再看做法。** V-Skip 分成三步：

1. **產生並篩選推理鏈**：用一個老師模型對每組「圖片＋問題」寫完整的推理鏈，答錯的直接丟掉。
2. **雙路打分，聯集保留**：
   - 文字路徑：token 的 self-information，也就是 −log P，越好猜分數越低。
   - 視覺路徑：這個 token 在注意力裡分給圖片 patch 的總量。只取中間 25%～75% 深度的層，每層取最大的那個 head，再對層平均。
   - 兩條路各自用 (1−γ) 的百分位數當門檻，**只要其中一條過門檻就保留**。γ 是目標壓縮比，0.5 代表大約留一半。
3. **蒸餾成 LoRA**：用壓縮後的推理鏈對模型做 LoRA 微調（r=16，只加在注意力的投影層，3 個 epoch，8 張 RTX 3090）。推論時模型直接寫出精簡的推理鏈，不需要再算注意力或打分。

理論包裝是「視覺錨定的資訊瓶頸」（VA-IB）：在長度限制下，同時最大化推理鏈和答案的互資訊，以及推理鏈和圖片在給定問題下的條件互資訊。後者拆開來，就是「只看文字時的不確定性」減去「看了圖之後的不確定性」，也就是挑出那些只看文字猜不到、看了圖就很確定的 token。

讀到這裡我發現，整條流程其實就是 TokenSkip 的架構（用 LLMLingua-2 刪 token，再用 LoRA 微調），只是多了一條視覺路徑。不過論文在相關研究裡把 TokenSkip 描述成「讓多餘的 token 跳過某些層」，跟 TokenSkip 自己公開的說明對不太上。

實驗用 Qwen2-VL（2B、7B、72B）和 Llama-3.2-11B-Vision，基準是 MMMU 和 DocVQA 的驗證集，另外用 POPE 測物體幻覺。

## 結果

主表是 Qwen2-VL-7B（MMMU 看準確率，DocVQA 看 ANLS，延遲是端到端的秒數）：

| 方法 | γ | MMMU | 延遲 | DocVQA | 延遲 |
|:---|:---|:---|:---|:---|:---|
| 原模型（完整推理鏈） | – | 54.1 | 6.42 | 91.6 | 4.87 |
| 直接截斷 | 0.5 | 38.5 | 3.23 | 62.5 | 2.57 |
| LLMLingua-2 | 0.5 | 32.4 | 3.73 | 38.5 | 2.93 |
| ASCoT | 0.5 | 33.1 | 3.91 | 40.2 | 3.10 |
| V-Skip | 0.7 | 51.5 | 4.65 | 87.9 | 3.68 |
| V-Skip | 0.5 | 48.2 | 3.49 | 83.7 | 2.71 |

其他幾個我覺得有意思的數字：

- **顏色詞留下多少**：γ=0.5 時，推理鏈裡的顏色詞 LLMLingua-2 只留下 42.5%、ASCoT 48.2%、V-Skip 89.4%；物體名稱分別是 64.8%、69.5%、91.2%。
- **幻覺**：POPE 問的是「圖裡有沒有某個東西」，答案一半是有、一半是沒有。原模型回答「有」的比例是 50.4%，兩個文字方法壓縮後衝到 66.8%（ASCoT）和 64.5%（LLMLingua-2），F1 從 89.1 掉到 77.1 和 78.9；V-Skip 是 51.2%，F1 88.9。
- **聯集比交集好很多**：γ=0.5 時，隨機刪 27.5、只看文字 32.4、只看視覺 40.5（但語法錯誤率 11.2%）、交集 30.1、聯集 48.2（語法錯誤率 1.3%）。
- **模型越大越耐壓**：γ=0.5 時，2B 掉 8.5、7B 掉 5.9、72B 掉 3.2。
- **視覺分數要從中間層拿**：只用前 25% 的層是 41.5，最後 25% 是 46.8，全部平均是 47.1，中間層是 48.2。

## 讀完最在意的三件事

**第一，最可怕的是「通順的幻覺」。** POPE 那張表最讓我在意。壓縮後的模型不是明顯變笨，而是越來越愛說「有」：推理鏈裡的視覺證據被刪掉以後，它就退回語言上的常識，比如看到餐桌，就覺得應該也有叉子。推理鏈本身照樣通順，使用者看推理過程也看不出哪裡不對。明顯的錯誤大家會去檢查，流暢又有自信的錯誤才難發現，這也是我覺得這篇比「又快了幾倍」更值得記住的地方。

**第二，論文對「為什麼會被刪」給了兩個方向相反的解釋。** 圖 1 說，「紅色」被刪是因為它在語言上**太好猜**；可是方法那一節和 $45.20 的發票例子又說，視覺相關的 token 在語言上**很難猜**（困惑度高），所以被當成雜訊刪掉。這兩種說法方向相反，而且照 V-Skip 自己的文字路徑，分數高、難猜的 token 本來就會被留下來。另外，LLMLingua-2 其實不是用困惑度，而是一個只讀文字的 token 分類器，它根本看不到圖。

我自己比較相信的解釋是：問題出在「誰在算機率」。如果用看得到圖的模型自己來算 −log P，「紅色」之所以好猜，不是因為前面說了蘋果，而是因為**模型看到了圖**。越是靠圖片才說得出來的詞，模型越有把握，分數就越低，越容易被當成廢話，換句話說，接地接得越好的 token，越會被這種打分方式懲罰。這是我讀完覺得最諷刺的地方。

**第三，用注意力當「有沒有在看圖」的證據，我還不太服氣。** 論文引用對比學習（CPC）的理論，說注意力權重可以當成互資訊的下界；但它算的是語言模型解碼器裡的注意力，這部分是用「預測下一個 token」訓練的，不是對比學習。注意力也有不少已知的怪現象，例如某些 token 不管內容是什麼都會吸走大量注意力。層的選擇對結果影響不小（41.5 到 48.2），也說明這個訊號需要細調。

既然打分是離線做的，不怕多花一點算力，我反而想直接照 VA-IB 的式子算：同一個 token，用「有圖」和「沒有圖」各跑一次，看機率差多少。這才是式子裡「看了圖之後不確定性下降多少」的直接估計。

## 數字要對著表看

- **2.9 倍加速在表裡找不到。** 摘要和結論都說 2.9 倍，但 Qwen2-VL-7B 的主表裡，γ=0.5 時 MMMU 是 6.42 → 3.49 秒、DocVQA 是 4.87 → 2.71 秒，大約 1.8 倍，正文自己也寫 DocVQA 是 1.8 倍。
- **「幾乎沒有損失」要看壓多少。** γ=0.5 時 MMMU 掉 5.9、DocVQA 掉 7.9，我不會說這可以忽略。真的幾乎沒掉的是 γ=0.9（掉 0.5 和 0.8），但延遲只從 6.42 秒降到 5.89 秒。我覺得比較實際的是 γ=0.7：掉 2.6 和 3.7，快大約 1.3 到 1.4 倍。
- **直接截斷贏過兩個文字壓縮法。** 這是主表裡最讓我意外的一列：只把推理鏈截到一半（論文沒有定義，我猜是留前半），MMMU 38.5、DocVQA 62.5，都比 LLMLingua-2 和 ASCoT 好很多。我猜是因為視覺語言模型的推理鏈常常先描述圖片、再推理，留前半剛好保住了視覺描述；但這也讓我懷疑基準線是怎麼跑的。論文說 V-Skip 比 LLMLingua-2 快，是因為後者要「線上過濾」，看起來基準線沒有經過同樣的 LoRA 蒸餾。最公平的對照應該是 TokenSkip：一樣的 LoRA 訓練，只差打分方式，這樣才知道進步有多少來自視覺分數、多少來自訓練。
- **兩個 32.4。** 消融表裡「只看文字」的 32.4，跟主表 LLMLingua-2 的 32.4 一模一樣，我不確定它們是不是同一組實驗。
- **少了「不推理、直接回答」的對照組。** 表裡「完整推理鏈」的 MMMU 分數（2B 41.2、7B 54.1、72B 64.5），跟 Qwen2-VL 技術報告的分數（41.1、54.1、64.5）幾乎一樣。我不知道技術報告是不是用推理鏈測的，但少了這一列，就看不出推理鏈在 MMMU 上本身幫了多少。如果直接回答就有 54 分左右，那壓到 48.2 的推理鏈，等於比不推理還慢、還差，壓縮推理鏈的前提，是推理鏈本身有用。

## 放到家用顯卡上

這篇對個人研究者其實很友善：打分全部離線做，推論時只是多一個 LoRA，不用額外計算。LoRA rank 的消融表寫到，r=16 時訓練的顯存峰值是 18.5 GB（表裡沒寫是哪個模型，但準確率 48.2 跟 7B 的主表一樣，應該是 7B）。這是 8 張卡一起訓練時的數字，換成單卡要靠梯度累積，不過看起來一張 24 GB 的卡有機會放得下。

但「模型越大越耐壓」那張表讓我有點擔心。最怕壓的是 2B，掉了 8.5 分，作者的解釋是小模型的推理鏈本來就很密，沒什麼可以刪；可是在自己電腦上跑的，偏偏就是這些小模型。最需要省的模型，也最禁不起省，所以小模型可能更需要「看題目決定壓多少」，而不是一個固定的 γ。

## 我的疑問

- **訓練資料從哪裡來？** 論文沒寫老師模型是哪一個，也沒寫拿哪些資料產生推理鏈來蒸餾。MMMU 有公開答案的只有 dev（150 題）和驗證集（900 題），而評估用的就是驗證集，我很想知道訓練用的是什麼。
- **推理鏈很短。** 原模型在 MMMU 平均只寫 245 個 token，DocVQA 是 189 個，模型也都是 2024 年的。現在會長篇思考的視覺語言模型動不動就寫幾千個 token，那才是最需要壓縮的地方；視覺證據散在長推理鏈裡，被刪掉的風險可能更高，但這篇沒有測。
- **不壓縮時反而比較慢。** γ=1.0 的 V-Skip（6.54 秒）比原模型（6.42 秒）慢一點，可能是 LoRA 沒有合併回權重的開銷。差距很小，但「零額外成本」還是要看怎麼部署。
- **沒有公開程式碼。** 我讀的時候找不到程式碼，聯集門檻、層的選擇這些細節沒辦法自己確認。

## 讀完之後想試的事

1. **直接估計「看了圖多知道多少」**：同一個 token，用有圖和沒有圖（或換成空白圖）各算一次 log P，把差值當視覺分數，和注意力分數比較，看哪一個更能找出真正的視覺錨點。
2. **補兩個對照組**：「不推理、直接回答」和「TokenSkip（同樣的 LoRA 訓練）」，把推理鏈本身的價值、訓練的效果和視覺分數的效果分開。
3. **把 POPE 的「有」比例當成固定檢查**：以後看到任何壓縮方法（推理鏈、視覺 token、量化都一樣），都順手看模型是不是變得比較愛說「有」，這比只看準確率更早發現它開始脫離圖片。
4. **換成會長篇思考的小模型**：例如 Qwen3-VL 的小型 Thinking 版本，看視覺錨點在長推理鏈裡分布在哪裡，是不是大多集中在開頭描述圖片的那一段。

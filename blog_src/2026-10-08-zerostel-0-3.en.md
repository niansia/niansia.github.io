[Zerostel](https://github.com/zerostel/zerostel) [0.3.0](https://github.com/zerostel/zerostel/releases/tag/v0.3.0) came out on October 8. `zerostel checks` and `zerostel log` now list which tests failed, read from the output already recorded, for common test runners such as vitest, jest, pytest, go test and cargo test, and the MCP `checks` tool includes the list too. Every MCP tool now has a title and annotations that say what it does to your machine: only `rewind` can change project files, `checkpoint` adds a snapshot, the others only read, and none of them reach the network.

Guardrail rules now read a command the way the shell runs it. A rule like `git reset --hard*` used to miss `"git" reset --hard`, `\rm -rf x`, `sudo -u root rm -rf x` or the same command inside `bash -c '...'`. Now quotes, backslashes, wrappers such as `sudo` and `env`, and the program's full path are taken off before matching, so a rule can only match more than before, never less. Property-based tests now generate thousands of spellings of denied commands and paths on every run and check that each one is still denied.

The same day went into the project itself: CI runs on Node 26, the website no longer serves the site folder's README as a page, and a new [privacy page](https://zerostel.com/privacy/) says plainly that Zerostel collects nothing and keeps its records in `~/.zerostel` on your own computer. The Claude Code plugin moved to its own repository, [zerostel/claude-plugin](https://github.com/zerostel/claude-plugin), whose `dist/cli.js` is the same file as in the npm package, ready to be submitted to Anthropic's plugin directory ([#16](https://github.com/zerostel/zerostel/issues/16)). Next up: showing the failed tests in `zerostel ui` and the HTML report, and rewinding to the step where a given test last passed ([#20](https://github.com/zerostel/zerostel/issues/20)).
